下面给你一份面向你当前 `react-base-service` 基座的 **Long-Term Memory V2 优化设计文档**。

定位：

* 基于你当前已有 Memory P1-P3 实现；
* 不推翻现有设计；
* 参考 ZCode / Letta / Mem0 / Graphiti 思路；
* 目标是把 Memory 从“长期事实存储”升级为“Agent 长期认知系统”。

你可以直接作为后续重构设计文档使用。

---

# Agent Long-Term Memory V2 设计方案

版本：V2.0

适用项目：

```
react-base-service
```

目标：

将当前长期记忆系统从：

```
Memory Item 存储系统
```

升级为：

```
Agent Cognitive Memory System
```

支持：

* 用户个人偏好
* 用户画像
* 项目上下文
* 历史事件
* Agent 工作经验
* 多 Agent 共享记忆
* Memory 演化
* Memory 冲突处理
* Memory 审计与恢复

---

# 1. 当前 Memory V1 问题分析

当前设计：

```
tblLlmMemoryItem

+
tblLlmMemoryRevision

+
memory_write/read/list

+
reflection
```

优点：

* 有 resident / detached 分层
* 有 revision 审计
* 有 owner scope
* 有 reflection
* 有工具化访问

但是存在几个问题。

## 1.1 Memory 类型混合

当前：

```
MemoryItem
```

同时承担：

```
用户偏好

业务事实

历史事件

Agent经验

任务状态
```

导致：

例如：

```
用户喜欢 Go
```

和：

```
2026-09-01 完成 Memory V2 设计
```

没有本质区别。

需要拆分。

# 3. Memory 四层模型

## 3.1 Preference Memory

用户偏好。

例如：

```
用户喜欢：

- Go语言
- 架构图
- Mermaid
- 先总结后展开
```

特点：

* 高稳定
* 高价值
* 高频使用

存储：

```
memory_type=preference
```

示例：

```json
{
 "type":"preference",

 "key":"response.style",

 "value":{
    "summary_first":true,
    "detail_level":"high"
 },

 "confidence":0.95
}
```

---

## 3.2 Semantic Memory

事实记忆。

例如：

```
用户负责数据平台项目

项目使用 Go

系统包含 MCP Client
```

特点：

长期有效，但是不是每次都需要。

例如：

```
memory_type=fact
```

---

## 3.3 Episodic Memory

事件记忆。

记录：

```
发生过什么
```

例如：

```
2026-09-20:

用户决定采用 ZCode Protocol V4

原因:
支持 Desktop/Web/Mobile 多端
```

特点：

需要时间。

结构：

```json
{
"type":"event",

"time":"2026-09-20",

"summary":"确定客户端协议方案",

"participants":[]
}
```

---

## 3.4 Procedural Memory

Agent 自己学习出来的方法。

例如：

```
处理这个用户的问题时：

优先输出架构图

再输出代码

最后补充优化建议
```

类似：

Agent Skill。

# 4. 数据模型升级

## 新表设计

## 4.1 Memory Entity

替代：

```
tblLlmMemoryItem
```

新增：

```
tblLlmMemoryEntity
```

SQL：

```sql
CREATE TABLE tblLlmMemoryEntity
(
 id bigint,

 owner_type varchar(32),

 owner_key varchar(255),


 memory_type varchar(32),


 subject varchar(128),


 content text,


 confidence decimal(5,4),


 importance int,


 stability int,


 state varchar(16),


 created_at datetime,

 updated_at datetime
)
```

字段说明：

| 字段 | 作用 |
| ----------- | ------------------------------- |
| memory_type | preference/fact/event/procedure |
| confidence | 可信度 |
| importance | 重要程度 |
| stability | 稳定性 |

CREATE TABLE tblLlmPreference
(

id bigint,


owner_key varchar(255),


category varchar(64),


preference_key varchar(128),


preference_value text,


confidence float,


source varchar(32),


last_confirmed datetime

)
```

例如：

数据：

```

lsl


category:

response


key:

format


value:

喜欢输出架构图


confidence:

0.96

# 7. Memory Extractor

新增模块：

```
service/memory/extractor
```

职责：

从对话中发现：

* 用户偏好
* 新事实
* 事件

输入：

```
conversation messages
```

输出：

```json
[
{
"type":"preference",

"content":

"用户喜欢 Mermaid 架构图"
}
]
```

# 8. Conflict Resolution

新增：

```
Memory Resolver
```

解决：

旧：

```
喜欢简短回答
```

新：

```
希望详细分析
```

流程：

```
new memory

    |

find similar memory

    |

conflict?

    |

LLM compare


    |

create revision

```

不要删除历史。
