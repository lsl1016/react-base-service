# 斜杠命令支持技术方案

- 日期：2026-10-13（v2.0 由审计版方案定稿为技术方案，随实现落地）
- 定位：在对话输入框支持 `/` 唤起命令，交付 `/compact`、`/workflow` 两条内置命令与**自定义命令**（DB 存储 + 管理 CRUD + 模板展开）
- 参考实现：ZCode monorepo 的斜杠命令体系——命令目录单一权威源聚合、提交后由分发层解析、本地命令确定性执行 / 提示词命令展开后发模型
- 关联文档：[system/react_runtime.md](../system/react_runtime.md)、[定时触发工作流实现方案.md](../定时触发工作流实现方案.md)、[VSCode插件接入方案.md](../VSCode插件接入方案.md)（slash→executionMode 设想，P1 落地）

---

## 1. 背景与目标

### 1.1 现状

- 前端 SDK 已内建 `/` 触发基础设施（Lexical + `SlashCommandPlugin`：触发检测、浮层、键盘导航、tree-select），宿主经 `quickInsertItems` 注入清单；但现有「命令项」只是往输入框插入结构化标签 `<tag k="v">label</tag>`（ShortcutNode），由模型自行理解——**没有确定性执行的命令语义**。
- 后端没有斜杠命令解析代码，`userPrompt` 在 `prepareRuntimeRequest` 装配后直进 ReAct 循环。

### 1.2 目标

1. 输入 `/` 唤起命令菜单；命令目录由**后端单一权威源**聚合下发（内置 + 自定义），前端不维护白名单。
2. 三类命令语义（对齐 ZCode 的分发模型）：
   - **控制型**：后端确定性处理，不产生模型 turn（P0 用于未知命令报错、run 活跃拒绝等错误路径，机制为 P1 的 `/help`、`/new` 预留）；
   - **标记型**：以特殊标记进入正常 run 管线（`/compact` 触发强制压缩）；
   - **展开型**：提示词模板展开后替换 `userPrompt` 进入正常 run（`/workflow`、全部自定义命令）。
3. 自定义命令：DB 表 + app/route 作用域 + 管理 CRUD + `$ARGUMENTS` 模板展开，APP 接入方可自助创建。

### 2.2 约束（决定了设计的「不做」）

| # | 约束 | 对设计的影响 |
|---|---|---|
| 1 | 「不开 run 落一条会话消息」无能力：`ReactMessage.RunID not null`、Seq 按 run 计、历史回放 JOIN `tblLlmReactRun` | 控制型命令只发即时 `command_receipt` 事件（刷新不回放）；无 run 消息机制列 P2 |
| 2 | steering 准入/queue 晋升在内部重建 payload，排队命令会按普通 prompt 执行 | 命令一律不排队：准入处识别命令直接拒绝 |
| 3 | run payload 的「UI 显原文、模型看展开」不需要新 wire 字段 | 复用 `content`/`modelMessage` 双字段信封，`persistUserInput` 落 `content=命令原文` |
| 4 | 本项目 workflow = cron/manual 触发的无人值守 ReAct run（无步骤/依赖字段），步骤编排是 Plan Runtime | `/workflow` 展开词对齐「创建定时/手动触发的无人值守任务」 |
| 5 | 内置 meta tool 不做 app 隔离（app 作用域只作用于业务工具）；`app_config.go` 不是运行时配置挂点 | 开关挂 `ReactRuntimeConfig` yaml 能力族；工具用「原生条件注册 + 执行时按调用方 appKey 归属」实现隔离 |
| 6 | `sql/` 无自动 migration，带参查询接口惯例全 POST | 新表 = `init.sql` + `_v1.sql`；目录接口 `POST /react/commands/list` |

## 3. 总体架构

```
前端（复用 SlashCommandPlugin）
  输入 "/" → 浮层新增「命令」分组（目录启动时从后端拉取，与宿主 quickInsertItems 合并）
  选中命令 → 输入框插入 "/name " 纯文本（argument-hint 作描述展示）
  回车 → 现有 WS run 消息原文上送（run 协议主体不变）
      │
后端（新增命令分发层，位于 ws.go EventRun 分支、startWSRun 之前）
  解析首 token（含别名归一 compress→compact）
  ├─ 控制型（P0 仅错误路径：未知命令、run 活跃；机制为 P1 /help、/new 预留）
  │     → 就地处理：校验/报错 → 写 command_receipt 事件回推（不开 run）
  ├─ 标记型（/compact [instructions]）
  │     → payload 附加 forceCompact 指令 → dispatchRunExecution 正常 run
  │       → executeReactLoop 第 0 步强制压缩（复用全量压缩管线）
  └─ 展开型（/workflow、自定义命令）
        → 命令服务展开模板：payload.UserPrompt = 展开文本，附加 commandDisplay = 原文
        → dispatchRunExecution 正常 run
        → prepareRuntimeRequest/persistUserInput：content=原文（UI 气泡），modelMessage=展开文本（入模）
```

与 ZCode 的对应关系：控制型 ≈ ZCode 本地命令、标记型 ≈ ZCode `/compact` 特殊 turn、展开型 ≈ ZCode `/workflow` + 自定义命令（`customCommandPromptResolver`）。

## 4. 详细设计

### 4.1 命令解析与分发（后端核心）

#### 4.1.1 新增 `service/command/` 包

职责：命令注册表、首 token 解析、别名归一、参数切分（引号感知）、模板展开、目录聚合。依赖仅 `models/llm` + `components/route` + `components/params`，**不 import react/plan/workflow**（保持依赖方向，与 plan→react 分流同理由）。执行胶水（改 payload、写回执）留在 controller 层。

```go
type CommandKind int // CommandControl | CommandFlaggedRun | CommandExpansion
type ParsedCommand struct {
    Name      string
    Args      string
    Kind      CommandKind
    Directive *RunDirective // FlaggedRun: ForceCompact / CompactInstructions
    Expansion *Expansion    // Expansion: Prompt(展开文本) + Display(原文)
}
func Parse(userPrompt string, catalog []CatalogItem) (ParsedCommand, bool)
```

内置命令表（代码内定义，含 name/别名/kind/argumentHint/description）：

| 命令 | 别名 | kind | argumentHint |
|---|---|---|---|
| `/compact` | `compress` | FlaggedRun | `[附加摘要指令]` |
| `/workflow` | — | Expansion | `<任务描述>` |

保留名集合：上表全部名称与别名 + `plan`、`react`（P1 executionMode 映射预留）+ `help`、`new`（P1 低成本命令预留）。自定义命令名冲突在创建时与服务装载时双重校验。

#### 4.1.2 拦截点：ws.go EventRun 分支

位置：[ws.go:198](../../controllers/http/react/ws.go#L198) `case reactService.EventRun` 内、`startWSRun` 之前：

1. 反序列化 payload 后调 `command.Parse`；
2. 未命中命令 → 原样走 `startWSRun`（零行为变化）；
3. 命中 → 按 kind 分流（控制型就地处理写回执；标记/展开型改写 payload 后仍走 `startWSRun` → `dispatchRunExecution`，复用全部现有 run 生命周期管理）。

#### 4.1.3 回执事件 `command_receipt`

- 事件常量加进 [internal/core/events.go](../../service/react/internal/core/events.go)，经 `core_bridge.go` 别出到 react 门面（门面同步测试兜底）。
- 载荷：`{ command, result: ok|rejected|error, reason?, message? }`，reason 词汇仿 steer 回执：`run_active`、`unknown_command`、`command_disabled` 等。
- 前端：event-reducer 新增 case → `role:'notice'` step → `NoticeChip` 渲染，不新造渲染路径。

#### 4.1.4 run 活跃与多入口一致性

- run 活跃期（`runMsgCh != nil`）收到命令：在进入 `HandleWSSteer` 之前识别 → `command_receipt(rejected, run_active)`，不排队。
- 防「排队晋升丢语义」双保险：steering 准入与 queue 晋升两处的准入判定中加入命令首 token 检查，识别为命令则拒绝入队。

#### 4.1.5 展开型的落库与入模（双字段信封）

- ws.go 展开后：`payload.UserPrompt = 展开文本`，`payload.CommandDisplay = "/name args" 原文`（`ReactRunPayload` 新增可选字段）。
- `prepareRuntimeRequest`：`persistUserInput` 与 `buildUserMessageContent` 处取 `CommandDisplay`（缺省回退 `UserPrompt`）作为 `content`（展示/落库），`UserPrompt`（展开文本）进 `modelUserMessage`——与 skill trigger 完全同构。历史回放、会话标题生成自动一致。

### 4.2 命令目录与下发

- `POST /react-base-service/react/commands/list`，body `{appKey, routeValues}`，挂 `reactGroup`（AnonymousAuth 语义与 `/models` 同款）。
- 服务端：`GetActiveAppByKey` 校验 app → `GetReactRuntimeConfigForApp(appKey)` 取 `slash_command.enabled` → 聚合：内置表（workflow 命令受 `llm.workflow.enabled` 联动剔除）+ DB 自定义命令（status + app/route 前缀匹配，复用 `BuildRoutePrefixes`）。
- 返回项：`{ name, description, argumentHint, source: builtin|custom, group }`。

### 4.3 /compact（标记型）

**语义**：手动触发当前会话全量压缩；可选附加指令影响摘要侧重。结果对用户呈现为一条分隔线（复用 `CompactDivider`），入模为 `compact_summary` user 消息——与自动压缩完全同构。

1. `ReactRunPayload` 新增 `CommandDirective`（`ForceCompact bool` + `CompactInstructions string`），ws.go 解析 `/compact foo` 后置位。
2. `prepareRuntimeRequest` 快照进 `runtimeRequest`（仿 `appAllowPlan` 快照）。
3. `executeReactLoop` 循环顶部：`step == 0 && req.forceCompact` 时调用 `maybeCompactContext` 的**强制版**（`force bool` 参数绕过水位判定，其余逻辑原样复用）。
4. `buildLLMCompactSummary` 增加 `extraInstructions` 参数：非空时在摘要提示词尾部追加「Additional Instructions」块。
5. 用户气泡：`/compact` 原文落库为 `user_input`，随后一条压缩分隔线。
6. 空会话/消息太少：压缩函数已有的空区间保护返回 skipped，回执提示「上下文已最新，无需压缩」。

**不做**：压缩核心抽离为独立服务函数（P2 评估独立合成 run）；忙时队列化（P2）。

### 4.4 /workflow（展开型）

#### 4.4.1 语义

引导模型创建**定时/手动触发的无人值守任务**（对齐 `tblLlmWorkflow` 真实模型），不引导步骤编排。

#### 4.4.2 展开模板（内置，代码内定义）

```
为以下任务创建并启动一个无人值守 workflow（定时或手动触发的完整自动执行任务）：
$ARGUMENTS

请先用 ask_question 向用户确认关键参数（触发方式 cron/manual、cron 表达式、超时、
步数上限、通知 webhook 是否需要），然后调用 create_workflow 工具提交定义。
create_workflow 会返回 workflow_key；如用户要求立即执行，再调用 dispatch_workflow。
```

#### 4.4.3 模型侧工具 `create_workflow` / `dispatch_workflow`

**注册方式：`runtimeToolDefinitions()` 原生条件注册**（create_plan/delegate_agent 同款先例），受 `llm.workflow.enabled` 门控——工具随 run 装配动态可见，关闭时模型根本看不到。

- **app 隔离的实现方式**：工具定义全局可见，但执行时以**当前 run 的 appKey/userName/routeValues 作为 workflow 归属**落库（`CreateWorkflowDef` 的入参即含 app_key/user_name/route_values）——创建的资源天然归属调用方，等价于业务工具的作用域效果。
- 底层直接调 `workflowService.CreateWorkflowDef / DispatchWorkflowDef`（已含校验、manager 同步、goroutine 跟踪），不绕 HTTP。
- 风险级 `medium`：走现有 tool_confirm HITL 确认链路。
- 门控三处联动：展开侧（未开时 `/workflow` 按普通 prompt 原文上送）、目录侧（命令清单剔除）、工具侧（不注册）。

### 4.5 自定义命令

#### 4.5.1 数据模型：新表 `tblLlmCommand`（照 systemprompt 样板）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uint PK autoIncrement | — |
| command_key | string, 唯一索引 | UUID 业务键（同 `skill_id` 惯例） |
| name | string, not null | `^[a-z0-9][a-z0-9_-]{0,31}$`；保留名双重校验；**app_key + route_values + name 组合唯一** |
| description | string | 一行描述，缺省取正文首行 |
| argument_hint | string, default '' | 参数提示，前端菜单展示 |
| content | mediumtext | 提示词模板正文（markdown，上限 100KB），支持 `$ARGUMENTS` / `$N` |
| app_key | string, not null | `default` 伪 app 全局语义沿用 |
| route_values | string | JSON 串，`BuildRoutePrefixes` 前缀 IN 匹配 |
| status | int, not null, default 1 | 启用/停用 |
| created_by / updated_by | string, default '' | 审计字段 |
| created_at / updated_at | time.Time | — |
| deleted_at | soft_delete.DeletedAt | gorm 软删 |

查询索引 `(app_key, route_values)`。文件：`models/llm/command.go`（结构+CRUD 抄 system_prompt.go）、`components/params/command.go`、`controllers/http/command/`、`router/http.go`、`sql/init.sql` + `sql/command_v1.sql`。

#### 4.5.2 模板展开

- `$ARGUMENTS`：全部参数原样替换；`$1`/`$2`…：位置参数（引号感知切分）。
- 模板未用占位符且参数非空：参数以 `User arguments:` 块追加尾部。
- 展开后包装头：「执行自定义命令 /name，按以下指令处理：」。
- **不做** shell 动态展开（`` !`cmd` ``）。

#### 4.5.3 管理面

playground 通用 management 注册表加一项（[web/react/index.js:639](../../web/react/index.js#L639) 模式）获得列表/新建/编辑/删除 tab。编辑表单字段：name、description + argument-hint、content 模板。

### 4.6 配置开关

- `llm.react.slash_command.enabled`：挂 `ReactRuntimeConfig` 能力族（steering 同款 `*bool`，默认关）。关 = ws.go 拦截层直通、目录 API 返回空、前端不显示命令分组。
- per-app 细分（P1）：`runtime_setting.go` Override 组或 `tblLlmApp` 三态列，二选一 P1 定。
- `/workflow` 额外受 `llm.workflow.enabled` 联动，不新增开关。

### 4.7 前端改动（SDK）

1. **命令项类型**：[types.ts](../../web/sdk/ui/editor/types.ts) 联合类型新增 `AgentCommandQuickInsertItem`（`kind:'command'` + `command:{name, argumentHint}`）；同步 `getSearchText` 类型假设。
2. **插入行为**：`insertItems` 加分支——`kind==='command'` 时 `$createTextNode('/name ')` 替代 ShortcutNode，**text 触发与 shortcut 触发两条路径都覆盖**。分组零改动（`groupItems` 数据驱动，`group:'命令'` 自动成组）。
3. **目录拉取**：`SessionManager.listCommands()` → `AgentClient.listCommands()`；`mountAgentUI` 在 connect 后自动拉取（失败静默降级），与宿主 `quickInsertItems` 合并；插件渲染条件改为「quickInsertItems + 命令目录合计非空」。
4. **回执渲染**：`command_receipt` → `role:'notice'` step → `NoticeChip`；compact 渲染零改动。
5. **已知退化（接受）**：纯文本 `/name` 不参与跨会话历史输入反解析，退化为纯 text part；会话内展示不受影响（`displayParts`）。

## 7. 风险与应对

| # | 风险 | 应对 |
|---|---|---|
| 1 | run 活跃期命令一律拒绝的体验取舍 | 回执明确提示「run 结束后重试」；P2 队列化 |
| 2 | 命令回执不落库，刷新后不可见 | 初版接受（回执是即时操作反馈）；P2 统一解决 |
| 3 | 自定义命令模板的提示注入面 | 创建者=APP 管理员（信任级别同 systemprompt）；包装头明示；不做 shell 展开 |
| 4 | 多入口扩张必须复用同一分发函数 | 分发收敛在 `service/command/` + controller 薄胶水；新入口接入时标注 |
