# 运行时配置新增联网能力开关（web_fetch / web_search 共用总开关）

## 1. 背景与目标

web_fetch（网页抓取）与 web_search（SearXNG 检索）的启停此前只能改 `custom.yaml` 并重启生效，运营期无法在线调整。本次把两个工具的**共用总开关**接入既有「运行时配置」面板：单卡片「网页检索」+ 一枚开关同时启停两个工具（状态天然同步），取值优先级为 **DB 覆盖 > custom.yaml > 内置默认值**（字段级），yaml 始终兜底。

面板只暴露总开关：web_fetch 的抓取预算/超时、web_search 的搜索服务连接参数（kind/base_url/api_key）仍归 yaml 管。同时为本地/容器环境接入 SearXNG 实例，web_search 开箱可用。

## 2. 代码改动

### 2.1 联网总开关（单设置键 `web`）

- `conf/runtime_setting.go`：`RuntimeSettingOverride` 快照扩至四组（subagent / context / memory / web）；新增 `WebAccessSettingOverride`（仅 `Enabled` 指针）与 `applyWebFetchOverride` / `applyWebSearchOverride` / `EffectiveWebFetchConfig` / `EffectiveWebSearchConfig`——同一份覆盖分别合并进两个工具配置，保证两工具开关恒同步；面板生效视图与引擎消费共用口径。
- `conf/config.go`：`GetReactRuntimeConfig` 在 subagent 段后把 `GetRuntimeSettingOverride().Web` 同时合并进 WebFetch / WebSearch；数字参数默认值仍由 `Effective*` 方法按需兜底。
- `service/setting/webaccess.go`（新增）：设置键 `web` 的 Get/Update 服务（`webAccessOverrideJSON` 存储结构与 load/validate/merge 辅助），落库后立即刷新覆盖快照，clearFields 清除覆盖回落两工具各自的 yaml 开关。生效视图额外透出 `configured`（web_search 连接参数完整性），半配置状态允许保存开关但引擎注册门控只拦截 web_search（web_fetch 不受影响）。
- `service/setting/setting.go`：`refreshOverrideFromDB` 读入 web 覆盖注入快照。
- `controllers/http/setting/webaccess.go`（新增）+ `router/http.go`：`POST /setting/web/get|update`（跟随既有 setting 路由鉴权与渲染模式）。
- `components/params/setting.go`：`UpdateWebSettingReq` / `WebSettingResp`。
- 引擎消费点统一改经 `conf.GetReactRuntimeConfig()` 取生效配置，消除「面板已关但工具仍注册/可执行」的双口径：`meta_tools.go`（工具注册门控）、`execution_profile.go`（AllowWebFetch/AllowWebSearch 档案位）、`web_fetch.go`（抓取执行）、`web_search.go`（档案门控 + 检索执行）。
- `web/react/index.js`：`settingCards` 新增「网页检索」单卡片（kind 标注 `web_fetch + web_search`，一枚总开关行，交互与 subagent/memory 卡一致）；卡片头状态徽标支持卡片级 `badge(data)` 自定义——半配置状态显示「已开启·检索配置不完整」红色警示徽标。

### 2.2 SearXNG 本地/容器接入

- `deploy/searxng/settings.yml`（新增）：SearXNG 实例配置——formats 开启 `json`（API 输出，默认只有 html）、`limiter: false`（内网使用，防 bot 限流会误拦 JSON API）、随机 secret_key。
- `docker-compose.yml`：新增 `searxng` 服务（容器名 `react-base-searxng`，宿主机 `${SEARXNG_HOST_PORT:-8888}` → 容器 8080，healthcheck `/healthz`）。
- `.env`：固化 `SEARXNG_HOST_PORT=8888`。
- `dev.sh`：`deps`/`up`/`stop`/`status` 纳入 searxng 容器。
- `conf/mount/custom.yaml`（本机开发）：`web_search.enabled: true`，`base_url: http://127.0.0.1:8888`（连容器映射端口，与 MySQL/Redis 连法一致）。
- `deploy/compose/conf/mount/custom.yaml`（容器发布形态）：补 web_fetch / web_search 段，`base_url: http://searxng:8080`（compose 内网 DNS，与 searxng 服务同网络）。

## 3. 影响范围

- 接口：新增 2 个 `/setting/*` HTTP 端点（`/setting/web/get|update`）；无 WS 协议变更。
- 数据库：复用 `tblLlmRuntimeSetting` 表，新增 `web` 设置键行；无需执行 SQL。
- 配置：不新增 YAML 字段；`web_fetch.enabled` / `web_search.enabled` yaml 语义不变（降级为兜底基线，清除面板覆盖后两工具分别回落各自 yaml 开关）。
- 行为兼容：无 DB 行/无覆盖时引擎行为与改动前完全一致；`service/react`、`service/setting`、`conf` 全量测试通过。
- 生效语义：保存后新 run 生效（run 初始化时装配工具集），运行中 run 不受影响；多实例约 10 秒内拉平。
- web_search 半配置状态：开关开启但 `kind=searxng + base_url` 不完整时该工具不注册、调用被拒（既有门控语义不变），面板以警示徽标显式提示，web_fetch 不受影响。

## 4. 测试

- `conf/runtime_setting_test.go`：单覆盖同时作用于两工具配置的字段级合并、nil 无操作、连接参数不受覆盖误改、`GetReactRuntimeConfig` 两工具同步开/关、面板口径与引擎口径一致性。
- `service/setting/webaccess_test.go`（新增）：clearFields 校验（含未知字段拒绝）、增量合并/clear 优先/显式关闭区分/空现状、生效视图 source/baseline/override 判定（断言从 `conf.CustomConf` 实际状态推导，不依赖 yaml 加载）、configured 透出、请求类型字段适配冒烟。
- 真实环境验证：SearXNG 容器 healthy 且 JSON API 实测返回聚合结果（请求形态与 `searxngSearch` 一致）；`/setting/web/get` 返回 enabled+configured。
