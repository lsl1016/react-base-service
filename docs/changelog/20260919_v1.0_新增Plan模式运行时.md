# 新增 Plan 模式运行时

## 1. 背景与目标

此前计划能力仅有 ReAct 模式内的 `create_plan` 确认卡片：计划不落库、执行依赖用户发送"开始执行刚才的计划"的新消息、无步骤状态与恢复语义。本次按 [Plan Runtime v2 实现方案](../plan/20260919_Plan_Runtime_v2_实现方案.md)引入第二种执行范式：`executionMode=plan` 的 Run 由服务端 Planner 强制先生成结构化计划并全量持久化，Executor 逐步推进，等待与恢复不依赖原 goroutine。实现以 `feature/plan-runtime-v1` 分支为底本文件级移植，并完成方案 D1–D9 修正。

## 2. 代码改动

- `service/plan/`（新增，~2000 行）：`runtime.go`（入口与 Resume/Retry/Skip/Cancel）、`planner.go`（submit_plan 结构化输出 + 线性校验）、`executor.go`（CAS 步进、Step Prompt、等待、Finalizer、Attempt 超时）、`repository.go`（6 表读写与全部 CAS 事务）、`public_view.go`（公开视图与事件重建）、`emitter.go`（plan_view_update / plan_step_event）、`state.go`。
- `service/react/external_runtime.go`（新增）：plan → react 的桥接窄接口（PrepareExternalRun / RestoreExternalRun / CompleteText / CompleteStructured / RunScopedStep / PersistExternalFinalAnswer 等），react 包不反向依赖 plan。
- `models/llm/plan_runtime.go` + `sql/plan_runtime_v1.sql`：六张表（Execution/Version/Step/Attempt/Result/Wait）。
- `models/llm/react_run.go`：新增 `waiting_plan` 活跃态；纳入 `HasActiveReactRun`，**排除出 30 分钟 stale 过期**（D2：等待态权威在 PlanExecution，误过期会导致会话解锁而计划悬挂）。
- `controllers/http/react/ws.go`：分流抽取为 `dispatchRunExecution`（D1，controller 层保持 plan→react 单向依赖）；WS 上行新增 `plan_resume/plan_retry/plan_skip/plan_cancel` 并处理收尾竞态。
- `controllers/http/react/plan_execution.go` + `router/http.go`：HTTP 控制面 `/react/plan_execution/detail|events|resume|retry|skip|cancel`（与 SDK 既有调用路径一致）。
- `service/plan/runtime.go` 修正：Cancel 级联取消后续 PENDING 步骤（D3）；Resume 前置校验外层 Run 状态，`expired` 走显式复活路径、终态拒绝（D2）。
- `service/plan/executor.go`：启用步骤超时 `timeout_seconds`（缺省 600s，Attempt 级 `context.WithTimeout`，D4）。
- `models/llm/plan_runtime.go`：删除未使用的 `CREATED` 状态常量（D5）。
- `web/sdk`：InputArea ReAct|Plan 模式开关；`resumePlanWithResponse` 等四命令改为 WS 结构化帧（删除"伪装新消息"式恢复）；PlanRuntimeCard 新增确认/拒绝、步骤重试/跳过、取消与 EXTERNAL_TASK 手动恢复；原生 plan_runtime 卡片；`AgentPanel` 的 `plans` 空值保护（D7）；测试断言与实现语义对齐（D7）。
- `docs/system/plan.md`（新增模块文档）、`docs/CONVENTION.md`（模块枚举 + plan）、`README.md`（能力清单与边界表述）。

## 3. 影响范围

- 接口：WS run payload 新增可选 `executionMode`（缺省 react，旧客户端行为不变）；新增 6 个 `/react/plan_execution/*` HTTP 端点与 4 类 WS 上行命令。
- 数据库：新增 6 张表（`sql/plan_runtime_v1.sql` 可重复执行）；`tblLlmReactRun.state` 新增枚举值 `waiting_plan`（varchar，无 DDL 变更）。
- 配置：不新增 YAML 配置；复用 `llm.react.*`。
- ReAct 模式：主循环、事件协议、HITL、SubAgent 行为不变；唯一交叉点是 `waiting_plan` 参与会话活跃 Run 判定与 `plan/` agentPath 的历史过滤。

## 4. 测试验证

- `go build ./...`、`go vet ./service/plan ./models/llm ./controllers/http/react ./service/react`：通过。
- `go test ./models/llm ./service/plan ./service/react ./controllers/...`：全部通过（含更新后的 stale 过期条件单测：断言 `waiting_plan` 不进入清理条件）。
- `web/sdk` vitest：270 通过 / 2 失败（`quick-insert-tree`、`sql-client-tools`，为 main 基线预存的环境性失败，与本变更无关）/ 9 跳过。
- `bash scripts/check-docs.sh`：18 篇受管文档 0 问题。

## 5. 风险与兼容性

- Plan 等待期间同会话普通消息会被"run is active"拒绝，需先处理等待项（前端输入区已锁定并提示）——这是刻意的互斥语义。
- V1 不做自动 Replan、并行步骤、外部任务自动轮询与服务重启自动恢复；`WAIT_EXTERNAL_TASK` 仅支持手动恢复。PlanExecution 已全量落库，二期补 Resume Worker 与 Lease 即可演进为 Durable。
- 步骤超时缺省 600s：此前无超时的长步骤现在会被中断并进入重试轨道。
