# 新增 Plan 模式端到端测试档案与回放记录

## 1. 背景与目标

Plan Runtime（`executionMode=plan`）上线当日需要一套**真实模型 + 真实工具**的端到端验证：
既验证功能正确性，也把执行边界（超时、断连、并发、等待恢复）压到真实行为上。为此先构建了
Node WS 测试驱动跑出六场景结论与问题清单（[测试报告](../plan模式E2E测试报告.md)），
随后驱动修复复测通过。本次把这套验证沉淀为项目长期资产，沿用
`tests/multi-agent/` 已确立的「场景库 + 结果档案」格式，并新增「回放记录」一层：
从服务导出各场景实测会话的权威回放流（与 `/react/replay` 回放页同源），让后续任何人
不改环境也能对照查看当时的会话级事件与最终视图快照。

## 2. 代码改动

- 文件：`tests/plan-e2e/driver.js`（此前随测试报告提交，本次无改动，登记为档案组成）
  - WS 客户端封装：事件流消费、`plan_view_update` 视图快照提取、`waitUntil` 轮询断言、
    HTTP 工具（统一 `errNo===0` 成功判定）。
- 文件：`tests/plan-e2e/run_scenarios.js`
  - 文件头新增**场景清单注释**（s1–s6/t7 → scenarios/ 编号对照与一句话说明）；
  - 新增场景 `t7`（步骤超时分类修复验证：timeoutSeconds=60 + sleep(90) + Retry 复位断言）；
  - 修正 s4 终态判定竞态（HTTP cancel 后以视图状态翻转为权威信号，避免探针 error
    事件污染 done/cancelled/error 三态判定）。
- 文件：`tests/plan-e2e/mutex_probe.js`：会话并发互斥独立探针（sessionId 置于 WS 消息
  顶层的正确构造，两态均验证被 6000100 拒绝）。
- 文件：`tests/plan-e2e/export_replays.js`（新增）
  - 按 REPLAYS 映射调用 `POST /react/session/events` 导出实测会话回放，落盘
    `replays/<编号>-<场景>.json`（含导出时间、plan/session ID、预期结论与回放体），
    并生成 `replays/manifest.md` 索引。
- 文件：`tests/plan-e2e/scenarios/01–07*.md`（新增 7 篇，沿用 multi-agent 场景文档格式）
  - 每篇含：场景函数、验证维度、目的、触发语料、预期断言、已知边界/历史教训、结果指针。
- 文件：`tests/plan-e2e/replays/*.json + manifest.md`（新增 8 份回放 + 索引）
  - 7 个场景代表运行 + 1 份修复前「超时误判为取消」Bug 证据样本（98 号）；
  - 修复前基线（S1/S3/S5/S6）与修复后复测（S2/S4/T7）在 manifest 中标注。
- 文件：`tests/plan-e2e/README.md`（新增）
  - 场景总览表、文件职责、运行方式、**驱动侧已知坑四条**（sessionId 顶层、取消终态信号、
    HTTP Retry 同步语义、run payload 必带 modelKey）、结果归档约定。
- 文件：`docs/plan模式E2E测试报告.md`（新增）
  - 完整测试报告：环境、六场景结果、聚合统计、问题清单 P1–P8、已验证能力清单（21 项）、
    修复复测记录（§10）。

## 3. 影响范围

- 接口：无新增/变更（回放导出复用既有 `/react/session/events`）。
- 模块：`service/*` 运行时零改动，纯测试与文档资产。
- 配置/数据库：无。`tests/plan-e2e/.gitignore` 保持 `artifacts*/` 运行产物
  （单次可达 5 万+条事件/数十 MB）不入库。
- 仓库体积：回放 JSON 为会话级摘要（每份 3–6 条事件 + 最终视图快照），入库体积可忽略；
  步骤级原始事件流可按 manifest 中的 planExecutionId 从 DB / `/plan_execution/events` 重建。

## 5. 风险与兼容性

- E2E 依赖真实环境（依赖容器、:8180 服务、glm-4.6 模型、`data/repo-mirrors` 镜像库、
  `demo-app` caller），**不适合接入 CI 常规门禁**，定位为发布前人工/半自动验证档案。
- 回放 JSON 含实测会话的标题与助手回答快照（内部测试数据，无敏感凭据）；若后续用于
  对外开源仓库，需评估是否剥离。
- 回放为静态归档：服务回放协议若演进（事件字段变更），历史 JSON 不随迁，仅作当时快照。
