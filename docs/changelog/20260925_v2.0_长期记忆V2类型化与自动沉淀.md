# 20260925 v2.0 长期记忆 V2 Phase 1-2：类型化与自动沉淀

## 变更概述

按《docs/plan/长期记忆V2实施计划-Phase1-2.md》完成长期记忆 V2 的前两个阶段：

- **Phase 1 记忆类型化**：`tblLlmMemoryItem` 新增 `memory_type / confidence / importance` 三列；写核心、模型工具、管理面、分节渲染全链路打通；`preference` 类型不论层级全文注入「用户偏好」节并优先占用常驻预算。
- **Phase 2 自动沉淀**：新增 `service/memory/extractor` 与 `service/memory/resolver`；`compact_end` 后异步执行「LLM 抽取候选 → 确定性预过滤 → LLM 批量冲突消解（ADD/UPDATE/SUPERSEDE/SKIP）→ 统一写核心落库」流水线；与 reflection 触发点互斥（extractor 优先）。

## 变更明细

- `sql/memory_v2_upgrade.sql`（新增）：存量环境三列 + 索引增量脚本；`sql/init.sql` 同步 DDL。
- `models/llm/memory.go`：MemoryItem 类型化字段与归一化函数；`MemoryItemFilter.MemoryType`；`FindActiveMemoryItemsLikeOwner`（resolver 候选召回）与 `CountActiveMemoryItemsGroupedByType`（指标）；新增来源常量 `extractor`。
- `service/memory/memory.go`：MutationInput 扩展（create 空值落默认 / update 空值保持原值）；非法类型/越界 confidence/importance 拒绝；rollback 对旧快照补默认值；RefreshMetrics 增加类型维度。
- `service/memory/runtime.go`：`RenderRuntimeContext` 分节渲染（偏好节/常驻节/目录节）；list/read 视图带 memoryType；Runtime 新增 `ActiveItems`。
- `service/react/memory.go`：memory_write 增加 `memoryType` 入参；memory_list 增加类型过滤；视图同步。
- `service/react/memory_extractor.go`（新增）：触发层——冷却、防自触发、goroutine 隔离、`llm.GetClientWithUserModel` 直连适配 `extractor.LLMInvoker`。
- `service/react/memory_reflection.go`：冷却表重构为通用 `scopedCooldownTable`（与 extractor 共用实现）。
- `service/react/runtime_support.go`：compact_end 挂钩改为 `maybeTriggerMemoryMaintenance`（extractor/reflection 互斥分发）。
- `service/react/runtime_services.go`：memoryRuntime 接口增加 `ActiveItems`。
- `conf/config.go` + `conf/mount/custom.yaml`：`ReactMemoryExtractorConfig`（默认关闭）。
- `components/metrics/metrics.go`：`react_memory_items_by_type`、`react_memory_extractor_total`。
- 测试：渲染分节/偏好回退、extractor JSON 鲁棒解析与预过滤、resolver 全决策路径与守卫（locked/幻觉 ID/写限/乐观锁重试/LLM 故障）、LIKE 条件防回归。

## 兼容性

- 存量库执行 `sql/memory_v2_upgrade.sql` 后旧行自动为 `fact/0.800/3`，行为兼容；未执行前新版查询引用新列会报错，需先执行脚本再发版。
- `extractor.enabled` 默认 false：不开启时运行时行为与 V1 完全一致（仅多出三个默认值字段）。
- 修订快照自动携带新字段；Phase 1 之前的旧快照回滚自动补默认值。
