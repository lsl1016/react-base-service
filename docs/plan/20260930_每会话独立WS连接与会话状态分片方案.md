# 每会话独立 WebSocket 连接 · 会话状态分片 — 实施方案与任务清单

- 日期：2026-09-30
- 状态：实施中
- 关联讨论：切换会话断联问题、单页面多会话并行、跨连接 run 准入语义

## 一、背景与问题

当前实现"单连接 = 单会话 = 单 run"：

1. **切换/新建会话被三层拦截**：UI 新会话按钮运行中禁用（AgentPanel `newSessionDisabled`）；`newSession()/switchSession()` 在 `isRunInProgress()||recovering` 时静默返回；即使绕过，WS 读循环的 `runMsgCh` 是连接级单槽，连接上已有 run 时任何 run 消息（含其它会话）被转 steer 准入。
2. **run 生命周期绑定连接**：断连 → `close(runMsgCh)` → run goroutine 收到 `ErrReactClientDisconnected` 中断。因此切换会话若通过断连实现，会杀掉正在跑的 run。
3. 前端 `AgentClient` 是单会话状态机：一份 reducer 状态、一个 `isRunInProgress`、`handleEvent` 不分会话直接 `applyEvent`。

结论：后端引擎/DB 完全支持多会话并行（per-run goroutine、per-session 行锁），瓶颈只在连接与前端状态组织。

## 二、方案选型（三选一，选定 A）

| 方案 | 结论 | 理由 |
|---|---|---|
| **A. 一个会话一个 WebSocket 连接（选定）** | 后端零改动，隔离最好 | 现有后端本就按"单连接承载一个会话的 run"设计；seq 语义天然正确；一条连接断只影响一个会话 |
| B. 单连接多 run 复用（runMsgCh per-session map + seq per-run 改造） | 风险最高 | 需改后端路由与 seq 语义（连接级 seq 在多 run 交错下会误判丢包），出错面大 |
| C. 一个会话一个常驻 goroutine（actor） | 不采用 | 不解决当前痛点（run 本就 per-goroutine）；引入 actor 生命周期与多副本亲和性问题 |

### A 的关键设计

- 前端 `AgentClient` 内部把"会话运行时"抽成 `SessionRuntime`：每个会话持有 **自己的 WsClient + 自己的 EventReducer（AgentState）+ seq 游标 + 恢复态 + 事件聚合器**。
- `AgentClient` 退化为管理器：共享配置（callerKey/模型/hooks/工具注册表/REST SessionManager/IndexedDB 账本），管理 `Map<sessionId, SessionRuntime>` 与当前视图指针。**对外 API 保持兼容**（作用于当前会话）。
- 切换会话 = 换指针 + 目标会话懒恢复（本地账本 → 服务端 `session/events` 补齐），不触碰任何连接。
- 连接生命周期：当前视图会话 + 有活跃 run 的后台会话保持连接；**空闲后台会话延迟断开**（断开条件：无 run 且无 HITL 等待；切回时重连 + sync 恢复）。

### 已核实的支撑事实

- 后端 WS 升级无连接数限制；`wsEventWriter` 带互斥锁（并发写安全）。
- seq 对齐逻辑前端已按 runId 记录（`localLastSeqByRunId`），每连接单会话场景天然正确。
- IndexedDB 账本按 session 存取；steer/队列/自动续跑全部 per-session（DB 账本）。
- 跨连接对同一会话发 run：第二个请求被"会话级准入"接管（guide/queue/reject 三选一），回执发第二条连接——数据不丢、不双跑（ws.go:323-327）。可选优化：rejected 时区分 reason=`run_active_on_other_connection`。

## 三、边界（第一期不做）

- 断连/关页/刷新仍会打断对应连接上的 run（多会话下爆炸半径=该页面全部会话）——"断连不杀 run"属二期（run 与连接解耦 + 事件落库补发），按需另行立项。
- guide 注入的"半可见性"（第二连接只见回执不见后续进展）维持现状。

## 五、风险与注意点（实现时对照）

1. **空闲断开误杀**：断开前必须确认该 runtime 无 run 且无等待中 HITL（waiting_client_tool 状态）。
2. **后台 HITL 可见性**：后台会话 waiting 时用户看不到工具卡——徽标必须能提示"等待输入"。
3. **恢复逻辑归位**：掉线续跑（recovering 系列）整体属于单会话 runtime，注意 `pendingLiveRunPayload` 与 wsClient 的对应关系（每 runtime 自己的连接自己恢复）。
4. **executor 工具回调**：`ClientToolExecutor` 发送回包的 wsClient 要用发起会话的 runtime 连接（现在构造时绑定了单一 wsClient.send）。
5. **内存淘汰**：runtime Map 设上限（如最近 8 个），超出按 LRU 销毁（先断连再丢弃，账本在磁盘可恢复）。
6. **单连接 seq 语义不变**：无需动 `handleEvent` 的对齐逻辑，但测试要覆盖"两个连接各自流式输出"互不干扰。
7. **旧版兼容**：SDK embed 进二进制同版本发布，无灰度问题；后端无协议变化。
