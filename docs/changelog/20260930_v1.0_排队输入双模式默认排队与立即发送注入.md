# 排队输入双模式：默认排队 + 显式注入

## 背景

S3 队列管理（list/update/reorder/delete + QueueStrip）与 S2 自动续跑已落地，但存在两个体验断点：

1. **回车默认走 guide 注入而非排队**：run 运行中且无附件时，新用户消息被决策树直接准入为
   guide（下一个模型轮注入），队列里没有东西，QueueStrip（仅在有排队项时渲染）从不出现——
   用户以为"看不到排队内容、无法编辑删除"。
2. **排队项无法中途注入**：`queue_send` 在 run 活跃时被硬拒绝，QueueStrip 的"立即发送队首"
   按钮运行中禁用，用户只能等 run 结束自动续跑。

## 方案（双模式）

- **模式一（默认，回车）**：显式排队——run 完全结束后按 FIFO 依次自动执行（复用 S2 autoDrain）。
- **模式二（显式，队列条目）**：立即发送注入——把排队项晋升为活跃 run 的 guide，
  在下一个安全边界（整批 tool_result 落库后 / 纯文本 finish 判定前）进入当前对话。

## 改动

### 后端

- `ReactRunPayload` 新增 `SteerDelivery`（`""`=auto 决策树 / `"queue"`=显式排队）：
  `steerAdmissionDecision` 增加 `PreferQueue` 分支——running 本可 guide 时改判 queue
  （reason=`user_preferred_queue`）；QueueEnabled 关闭时偏好不生效（兜底注入优于拒绝）。
  WS 与 HTTP/SSE 准入路径（`admitSteeringInputTx`）统一从 payload 读取，无需改签名。
- `ReactQueueSendReq` 新增 `Mode`（`run` 默认 / `inject` 注入）：
  - run 活跃 + inject：`InjectQueuedItemAsGuide` 在 session 行锁事务内校验
    （活跃 run 为 running、非软着陆、行锁取 queued 项、payload 快照无附件、归属五元组）
    后调 `PromoteQueuedInputToGuideWithDB` 条件更新（status=admitted、delivery=guide、
    run_id 改写为活跃 run），回执走 `EmitSteerReceipt`（guided / rejected 带 reason）。
    校验不过返回 rejected 而非 error——排队项留在队列，不丢。
  - run 活跃 + run 模式：维持历史拒绝行为。
  - 空闲（任意 mode）：维持 `PrepareQueuedRunPayload` 晋升开新 run。
- 引擎零改动：注入后的行由既有 `drainPendingGuideBoundary` 在下一个安全边界消费，
  按会话 seq 与已有 guide 统一 FIFO，消费时发 `steer_drained`。
- `ReactQueueItem` 新增 `HasAttachments`（`ListSessionQueue` 从 payload 快照解析），
  前端据此禁用带附件项的注入按钮（guide 注入只支持纯文本，S1 纪律）。

### 前端（SDK）

- `RunPayload` 类型与 `sendSteerMessage` 发送时携带 `steerDelivery: 'queue'`——运行中回车
  默认排队；InputArea 既有占位文案"继续输入以排队后续修改..."从此与行为一致。
- `sendQueuedMessage(pendingInputId, mode?)`：inject 模式运行中不再忽略；实际发送的 mode
  按运行态校正（运行中→inject，空闲→run）。
- QueueStrip 每条排队项新增"立即发送"图标按钮（主色高亮）：运行中 → 注入当前对话
  （带附件项禁用并提示"将在 run 结束后自动执行"）；空闲 → 开新 run。移除底部
  "立即发送队首"按钮（每条按钮取代，避免双入口语义混淆），footer hint 按运行态更新。
- 注入成功的反馈链路复用现有事件投影：`steer_guided` 回执 → steerState 变化 →
  AgentPanel createEffect 触发 refreshQueue → 队列条消失；消费时 `steer_drained`
  notice"已注入新一轮对话"。

## 遗留与边界（对齐既有刻意设计）

- cancel/error/timeout 终态不自动续跑（留给用户决定），队列项保留待手动消费。
- 软着陆窗口与 HITL 等待（waiting_client_message/waiting_plan）绝不被注入打断：
  此时点"立即发送"收到 steer_rejected 回执，排队项保留。
- 进程重启不复活队列（`SettleStaleQueuedBySessionWithDB` 语义不变）。
