# 新增队列管理 API、SendMessage 与子代理看门狗（S3/A2）及前端接入

## 1. 背景与目标

S1/S2/Q1/A1 落地后仍剩三块缺口（方案 `docs/plan/20260925_Session与Steering机制借鉴方案.md` P2 阶段）：

1. **S3 队列管理**：排队输入只有"自动续跑"一条消费路径，用户无法查看/编辑/重排/删除队列，auto-drain 关闭时排队项无显式发送入口；
2. **A2 SendMessage**：父 Agent 无法向已委派的子代理补发信息（ZCode messageSink 等价物），子 run 也没有墙钟看门狗；
3. **前端**：SDK 对 steer_* 六事件、notice_drained 与 react_notice 消息零处理，Steering/通知在界面上不可见。

## 2. 代码改动

### S3 队列管理（后端）

- 文件：`service/react/queue_manager.go`（新增）
  - `ListSessionQueue`：按 FIFO 查询会话排队输入，回显 queueEnabled/autoDrain 配置；
  - `UpdateQueuedItem`：编辑排队内容——事务内**行锁读**确认仍是 queued 后无条件改写（规避 MySQL"值未变化时 RowsAffected=0"与 claim 判定混淆，实测曾误判"状态已变化"）；
  - `ReorderSessionQueue`：IDList 必须恰为当前队列排列（`planQueueReorder` 纯函数校验），事务内锁定读重新校验后按请求顺序连续改写账本 seq（从最小 seq 起）——重排同步落账本，防冷热事实分叉；
  - `DeleteQueuedItem`：置 cancelled（用户删除语义，条件更新与晋升互斥）；
  - `PrepareQueuedRunPayload`：显式发送前加载排队项 payload 快照并携带 PromotePendingInputID（claim-once 在 createReactRunContext 事务内兜底）；
  - 归属校验复用 validateReactSessionContext 五元组。
- 文件：`controllers/http/react/queue.go`（新增）+ `router/http.go`：`/react/queue/{list,update,reorder,delete}` 四个 POST 端点。
- 文件：`controllers/http/react/ws.go`：WS 新消息类型 `queue_send`——显式发送一条排队输入，先回 `steer_drained` 再在同一连接开新 run（实时事件流与自动续跑一致）；与 EventRun 互斥。不提供 HTTP 发送入口（HTTP 无法回传 run 事件流）。
- 文件：`models/llm/react_pending_input.go`：新增 `ListQueuedBySessionWithDB/ForUpdateWithDB`、`GetQueuedByIDWithDB`、`UpdateQueuedInputSeqLockedWithDB`、`UpdateQueuedInputContentLockedWithDB`、`CancelQueuedInputWithDB`。

### A2 SendMessage + 看门狗（后端）

- 文件：`service/react/send_message.go`（新增）
  - 新 Meta Tool `send_message`（与 delegate_agent 同门控 profile.AllowSubagent，见 `meta_tools.go`/`execution_profile_access.go`）：父模型按 agent_path 或 run_id 定位**本 run 直接委派**的子 run，把 message 作为 guide 落账本（kind=user_input/delivery=guide/admitted），子引擎在既有模型步边界消费——完全复用 S1 机制（对齐 ZCode messageSink）；
  - 目标选择 `chooseSendMessageTarget`（纯函数）：活跃优先、同路径多委派取最新活跃、全终态时取最新终态行供明确报错；
  - 发送前软着陆拒收：目标子 run 正在收尾时拒绝（对齐 S1 收尾窗口不收 guide 的纪律）；
  - 发送后复核：账本行若已被终态结算作废，如实回报"消息未能消费"。
- 文件：`service/react/delegate.go`：`startSubAgentWatchdog`——`subagent.max_run_seconds`（默认 0=不限）到点以 ErrReactRunTimeout 取消子 run，同步/后台两条委派路径均挂接；`finalizeSubAgentRunError` 新增 timeout 终态映射；子 run 注册/注销软着陆标记（send_message 可见性）。
- 文件：`conf/config.go`：`ReactSubAgentConfig.MaxRunSeconds` + `SubAgentWatchdogDuration()`。
- 文件：`service/react/steering.go`：`settleRunPendingInputs` 增加 isOuterRun 参数——**子 run 的未消费 guide 一律 discarded，绝不降级会话队列**（子代理定向消息降级进主对话队列属语义错误，实测发现后修正）；fallback 降级仅限外层 run。
- 文件：`service/react/boundaries.go`：enterSoftLanding 对全部已注册 run 置位（含子 run）。

### react_notice 历史回放（后端）

- 文件：`service/react/history.go`：react_notice 消息映射回 `notice_drained` 历史事件（payload 携带信封正文 content），历史回放与实时事件同词汇。

### 前端 SDK 接入（web/sdk）

- `protocol/types.ts`：EventType 新增 steer_guided/steer_queued/steer_rejected/steer_drained/steer_delivery_changed/steer_discarded/notice_drained；新增 4 个 payload 接口（notice payload 含可选 content）。
- `runtime/types.ts`：Step.role 新增 'notice' + Step.notice 展示字段（text/detail/count）；AgentState 新增 `steerState` 投影（最新准入结论/队列长度/原因）。
- `runtime/event-reducer.ts`：7 个事件 case——回执类更新 steerState 并生成系统标记 step（引导已注入/已入队第 N 位/未接收原因），drained/discarded/delivery_changed 生成对应中文标记，notice_drained 携带信封正文可展开；系统标记**不透传 agentPath**，无论事件归属都落 main lane；历史回放走同一 switch 自动生效。
- `runtime/session-event-assembler.ts`：透传列表补 7 个新类型；cloneEvent 补 agentPath 透传。
- `ui/components/NoticeChip.tsx`（新增）+ `MessageList.tsx`/`turn-segments.ts`/`WorkBlock.tsx`/`message.scss`：系统标记条渲染（复用 compact-divider 风格，detail 可展开查看通知信封正文）。
- 重新构建 `dist/0.0.1.js|css`（vite build:lib + build:browser，browser 产物经 Go embed 对外服务）。

### 实测客户端（保留）

- `cmd/livetest/queue-manage`：ask_question 等待态排队 3 条 → HTTP list/update/reorder/list/delete 断言 → 作答后自动续跑按**重排后顺序**消费。
- `cmd/livetest/send-message`：后台委派 + send_message 补充消息 + 父 run 保持活跃 → 子代理消费补充消息 → 完成通知回灌。

## 3. 影响范围

- 接口：新增 `/react/queue/{list,update,reorder,delete}` 四个 HTTP 端点；WS 新增上行消息 `queue_send`；工具清单新增 `send_message`（模型可见，subagent 开启且未达深度上限时）。
- 配置：新增 `llm.react.subagent.max_run_seconds`（默认 0=不限）。
- 数据库：不新增表和列。
- 前端：SDK bundle 重建（0.0.1.js/css），历史与实时流新增系统标记条与 steer 投影；对未升级的宿主无破坏（未知事件类型透传不影响既有渲染）。

## 4. 测试验证

- `go build ./...`、`go test ./service/react/ ./service/tool/`、`go vet ./service/react/`：通过（新增 TestChooseSendMessageTarget/TestParsePendingInputID/TestSendMessageToolDefinition/TestSubAgentWatchdogDuration/TestPlanQueueReorder）。
- `cd web/sdk && npm run test:run`：40 个文件 294 用例全绿（新增 __tests__/steer-events.test.ts 6 用例）；`npx tsc --noEmit` 无错误；`npm run build` 重建 dist。
- `bash scripts/check-docs.sh`：28 篇 0 问题。
- 实测（go run main.go :8180 + docker 基础设施 + 浏览器）：
  - **S3 队列管理**（cmd/livetest/queue-manage）：等待态排队 3 条（steer_queued pend_17/18/19）→ queue/list 返回 3 条 → queue/update 改写 B（claimed=true）→ queue/reorder 倒序（claimed=true，复查 list 顺序 C,B,A 且 seq 连续改写为 1/2/3）→ queue/delete 删 A（queueLength=2）→ 作答后 run1 收敛，自动续跑按重排后顺序 steer_drained pend_22(C)→pend_21(B)→3 次 done——重排真实改变消费顺序。（首轮实测曾暴露两个问题并修复：重排时 MySQL 等值更新 RowsAffected=0 被误判"状态已变化"→改行锁读+无条件更新；错误包装 %!(EXTRA) 乱码→改 ParamInvalidf）
  - **A2 SendMessage**（cmd/livetest/send-message）：delegate_agent(background=true) 启动回执 → send_message 返回"消息已作为引导注入子代理 main/echo-agent" → 子代理 lane 上 steer_drained(pend_26)（补充消息在模型步边界被消费）→ 子代理最终答复包含"【补充要求已收到】"→ 完成通知回灌 notice_drained → 主 run done。账本两行均 guided、无残留。
  - **定向消息不降级**（实测驱动的设计修正）：早期场景中补充消息落在子代理最后边界之后，被 S2 fallback 误降级为会话排队输入——修正为子 run 未消费 guide 一律 discarded，并发复核路径覆盖。
  - **历史回放**：session/events 对早期通知会话返回 notice_drained 事件且携带信封正文。
  - **前端**：playground 加载新 bundle（含 steer_guided 处理）无 JS 错误、WS 连接成功；浏览器实际发送消息完成一轮"发送→流式→done"无回归；SDK 294 单测覆盖事件投影。

## 5. 风险与兼容性

- queue API 归属校验按会话五元组（user/caller/route/type），跨会话操作返回 param invalid；编辑/删除与晋升 claim 互斥，落空返回 claimed=false 或明确报错，无覆盖风险。
- send_message 只能寻址本 run 直接委派的子 run；跨 run/跨会话寻址被归属校验拒绝。子代理已结束/软着陆收尾时发送得到明确错误结果（模型可自行调整），消息绝不误投会话队列。
- max_run_seconds 默认 0，未配置时行为与历史完全一致；配置过小可能截断正常子任务（按 agent 平均耗时评估）。
- 前端旧版本 SDK 收到 steer_*/notice_drained 事件时按未知类型忽略（ws-client 白名单仅影响日志），不影响既有功能。
- 回滚方式：前端回退 dist 产物；后端 queue/send_message 均为增量端点与工具，回滚提交即可。
